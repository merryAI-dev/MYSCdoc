# 해양수산 MYSCdoc 개발·실험 기록

기록일: 2026-10-21

## 합의한 방향

- 기존 MYSCdoc UI/UX와 실제 앱 로직에서 해양수산 자료를 사용한다.
- Claude API만 우선 사용한다. 현재 검색은 텍스트 후보 검색과 Claude 문맥 선택이며, 학습 임베딩 구현은 아니다.
- 주체·대상·값·근거·조건·제약된다 등의 트리플 관계를 유지한다.
- 성장(배운 인사이트·정량적 해석), 성과(관계·파트너 진척), 성숙(기업 피드백)을 별도 다중 분류 속성으로 둔다.
- 분류와 사실 상태를 분리한다. 예정 관계를 실제 성과로 단정하지 않으며, 명시된 기록도 독립적으로 검증된 사실을 뜻하지 않는다.

## 반영 및 검증 상태

64개 문서를 가져왔고, 45개 문서에서 그래프가 추출됐다. 나머지 19개는 그래프 추출 결과가 비어 있지만 문서 자체는 남아 있다. 기존 트리플 833개가 변경되지 않았음을 스냅샷과 비교 확인했다. 텍스트 청크는 709개이며 임베딩 보유 청크는 0개다.

833개 트리플에 자동 분류를 추가했다. 성장 252개, 성과 348개, 성숙 235개, 미분류 101개다. 복수 라벨이므로 각 분류 수를 합산해 전체 건수로 해석하면 안 된다. 모두 미검토 상태이며 사람의 검토가 필요하다. ID 검증에 실패한 3개 배치는 최초 실패 기록을 보존하고 재시도해 완료했다.

Claude 키는 사용자 요청에 따라 로컬 `.env`에 저장했다. 파일 권한은 0600이며 Git 제외를 확인했다. 비밀값은 이 문서에 기록하지 않는다.

## 실제 앱 비교 실험

동일한 6개 질문을 다음 세 방식으로 실행해 실제 답변 18개와 출처·실행 시간을 저장했다.

| 방식 | 후보 선택 |
| --- | --- |
| BM25 | 기존 BM25 + 1홉 |
| CONTEXT | 기존 후보에서 Claude가 최대 12개 선택 |
| CONTEXT_EXPANDED | 최대 60개 후보에서 Claude가 최대 12개 선택 |

생성 모델은 Claude haiku 5.5이며 질문 재작성은 껐다. 답변 프롬프트는 세 방식에 동일하게 적용했다. decision을 확정 사실로 설명하던 표현을 수정하기 전의 응답은 별도로 보존하고 비교 기준선에서 제외했다. 분류는 문맥 모드 실행 전에 고정했고 BM25에서는 사용하지 않는다.

| 질문 | 관측 결과 |
| --- | --- |
| 더블티 첫 컨설팅 파일럿 계약 | 미해결. 확대 후보에서도 쿳션 자료가 섞였고, 첫 컨설팅의 직접 근거 회수에 실패했다. |
| 해송물산 자체 포장 확정 여부 | 세 방식 모두 미확정으로 답했다. 확대 방식은 팀 확인 및 고객 지정 포장사 활용 조건까지 회수했다. |
| 자일로랩스 약 98% 정확도 | 세 방식 모두 실제 고장이 아닌 시뮬레이션 기반이라는 한계를 설명했다. |
| 쿳션 파트너십·PoC 보장 여부 | 세 방식 모두 보장 없음과 피드백 이후 판단을 구분했다. |
| 더블티 항만 검증 기관 | DP World APAC·PNC를 모두 답했다. 더블티 문서 출처가 기존 4/12, 동일 후보 5/6, 확대 후보 12/12로 개선됐다. |
| 해송물산 100억 투자 계약 | 확대 방식은 직접 근거 0개로 기권했다. 기존 방식들은 다른 기업의 투자 KPI를 부가 설명했다. 계약 날짜·투자자는 세 방식 모두 만들어내지 않았다. |

문서 제목 기준 출처 정합성은 문장별 정답률이 아니다. 6문항 각 1회 실행이며 평가 기준은 작성자의 잠정 기준이다. 독립 정답 라벨, 반복 실행, 통계적 유의성 검증은 없다. 분류·출처 제목·후보 확대 효과도 분리하지 못했으므로 일반화된 정확도 향상을 주장하지 않는다.

관련 회귀 테스트 11개 및 `git diff --check`가 통과했다. 기존 앱 화면에서도 문맥 검색의 실제 답변과 분류 범례를 확인했다.

## 산출물 위치

실제 답변과 내부 자료는 저장소 상위 `experiments/marine-app-comparison/`에 로컬 보관한다. 이 경로의 자료는 이번 문서 커밋에 포함하지 않는다.

- `report.html`: 실제 답변 18개, 출처, 비교 해설
- `spec.json`: 질문과 잠정 평가 기준
- `bm25.json`, `context.json`, `context_expanded.json`: 실제 API 결과
- `bm25_original_status_prompt.json`: 프롬프트 수정 전 결과
- `graph_snapshot.json`, `classifications.json`: 원본 관계 및 자동 분류
- `review.json`: 잠정 검토 기록
- `myscdoc-context.png`: 기존 앱에서 실행한 답변 화면

## 다음 개발에서 이어갈 과제

1. 원문 구간·기업·사건 식별자를 연결해 다른 기업 근거의 혼입을 줄인다.
2. 조건·부정·예정 상태와 성장·성과·성숙 라벨을 사람이 검토한다.
3. 기업/사건 단위 홀드아웃, 분류 미사용 대조군, 반복 실행 및 동일 토큰 예산 비교를 설계한다.
4. 그 이후 문맥별 거리 학습과 성공·실패 기억 갱신을 별도 구현·검증한다. 현재 앱에는 연결하지 않았다.

이번 커밋은 현황 기록용이다. 기록된 코드 변경은 작업 트리에 있으며 이 문서 커밋에는 포함하지 않는다.
