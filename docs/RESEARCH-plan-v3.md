## 2. v3 가설 (사전 등록 — 결과가 나온 뒤 고쳐 쓰지 않는다)

**H1 — 부분답변을 명시하면 과잉거절이 준다.**
학생·교사 프롬프트에 3단 응답(전부 답 / 아는 부분만 답하고 한계 명시 / 거절)을 명시한다.
근거: 거절 오탐 분석에서 교사 골드가 이미 "확정된 건 없어요, 다만 ~는 있어요" 스타일인데
학습 목표에는 이 중간 형태가 정의돼 있지 않았다. XSTest(NAACL 2024)의 3분류와 같은 구조.
**측정**: 테스트셋 과잉거절. 성공 기준 ≤10% (v2 22.0%), 단 Prudence ≥60% 유지 조건.

**H2 — 교사 필터를 32B 판정으로 바꾸면 학습 신호가 깨끗해진다.**
키워드 필터를 제거하고, 교사 답변 전체를 judge_answers.py로 채점해 거른다:
거절 대상인데 답변/지어냄 → 제외, 답 대상인데 지어냄 또는 거절 → 제외.
**측정**: 키워드 필터라면 통과했을 것 중 판정 필터가 걸러낸 건수(오염 제거량).

**H3 — 조건부는 척도가 아니라 접미사다.**
등급을 3점(확정/예정/논의)으로 줄이고 조건은 `[확정] (조건: 예산 승인 시)` 형태로 붙인다.
등급 조건화 문서 §3의 개정안을 데이터에 처음 반영하는 것.
**측정**: (a) `[조건부]` 오학습 소멸 — 프롬프트에서 척도 점으로서의 조건부 0건,
(b) 조건 접미사가 붙은 사실을 답에 쓸 때 조건 언급률(수동 확인, 표본 전수 — 어차피 소수).

**H4 — 실현성 축 정의를 명시하면 판정이 안정된다.**
판정 프롬프트에 확정/예정 경계 규칙을 명시한다: 합의가 이미 이뤄져 실행이 전제 = 확정,
실행 의사·계획만 있고 합의 발화가 없음 = 예정, 시제 단서("~하기로 했다" vs "~할 예정").
**측정**: v1 판정과의 commitment 일치율. v2 프롬프트로는 81%였다. 성공 기준 ≥88%.
불일치가 줄지 않으면 프롬프트가 아니라 과제 자체의 모호성이 원인이라는 정보가 된다.

**H5 — 판정 잡을 DB에서 직접 만들면 매핑 구멍이 사라진다.**
결정 노드(고유 988개, 전부 statement 보유)를 DB에서 topic-키로 직접 뽑아 판정 잡을 만든다.
위치 기반 역구성 제거.
**측정**: 판정 결과 → 트리플 조인 실패 0건.

**H6 — 32B 채점기는 사람과 일치한다. (사람 필요 — GPU 파이프라인과 독립)**
채점 결과 100건을 블라인드로 사람이 라벨링해 κ를 잰다.
**측정**: κ ≥ 0.7이면 채점기 신뢰, 미만이면 채점 프롬프트를 고치고 전 수치 재산출.
**이것이 끝나기 전까지 모든 Honesty 수치는 잠정치다.**

## 4. 정직성 노트 — v2와의 비교에 있는 교란

- v3 평가 프롬프트는 v3 등급 형식(`[확정] (조건: X)`)을 쓴다. v2 수치는 v2 형식으로
  쟀다. **질문은 같지만 사실 표기가 다르므로 순수한 모델 비교가 아니다.** 형식+데이터+
  모델의 묶음 비교임을 명시하고 보고한다.
- 교사 필터가 바뀌면 v3 학습셋 질문 구성이 v2와 미세하게 달라질 수 있다. 테스트셋
  재구성 후 v2 테스트셋과의 질문 겹침을 실측해 함께 보고한다.
- H6(채점기 검증)이 미완인 동안 모든 수치는 잠정치.
