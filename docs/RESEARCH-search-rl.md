# Search RL 실험 설계 — 가설 20 (2026-07-27)

> 목표: EXAONE 1.2B가 mydoc 지식그래프 검색을 수월하게 하도록 RL로 개선한다.
> 문헌 정독(Search-R1, R1-Searcher, SearchGym, DeepRetrieval, RL-QR, StepSearch,
> ReZero, IKEA, SoG-R1, ZeroSearch, Agent Distillation)에 근거해 가설을 세우고
> 점진 검증한다. 각 가설: [근거] 문헌/실측 → [검증] 우리 실험.

## A. 환경 설계 (H1–H6)

- **H1. 우리 코퍼스(5,885트리플)는 지름길 위험 구간이다.** [근거] SearchGym: 3,600문서
  시뮬레이션에서 넓은 쿼리+반복확인 지름길 학습→실전이 전이 실패. ReZero: 341청크에서
  붕괴. [검증] 학습 중 쿼리 다양성·길이 분포 추적, held-out 질문에서 주기 평가.
- **H2. 사내 코퍼스는 기억-지름길이 없다는 강점이 있다.** [근거] SearchGym이 가상 개체로
  해결한 문제(모델이 위키를 암기)를 우리는 공짜로 얻음 — EXAONE은 MYSC 회의록을 본 적 없음.
  [검증] 검색 없이 답하기 baseline이 바닥인지 확인.
- **H3. 골드가 검색 불가능한 질문은 보상을 오염시킨다.** [근거] SearchGym 감사: 학습 데이터
  20.6% 결함이 붕괴의 원인. 해결책=해결가능성 보장(엣지당 15쿼리 중 ≥5 성공만 채택).
  [검증] Phase 0에서 전 노드 검색가능성 감사 후 불가능 노드 제외.
- **H4. 질문에 답이 문자로 들어가면 안 된다.** [근거] 답 문자열 에코만으로 hit 달성(자명한
  지름길). [검증] 질문 템플릿에서 outcome 문자열 제거 + 오염 검사 자동화.
- **H5. 순진 쿼리로 이미 top-1인 질문은 학습 신호가 없다.** [근거] RL-QR: 개선 여지(headroom)
  있는 질문이 학습을 견인. [검증] naive rank 분포 측정, rank>1 질문 비중 확보.
- **H6. 한/영 혼용은 우리판 Language-Mixing 결함이다.** [근거] SearchGym 결함 분류.
  [검증] 채점을 형태소 정규화 기반으로, EM 금지.

## B. 보상 설계 (H7–H11)

- **H7. 이진 hit 보상은 소형 모델에서 gradient가 사라진다.** [근거] GRPO는 그룹 내 분산이
  0이면 advantage=0. DeepRetrieval이 계단식 보상 사용. [검증] 계단식(top1=5, ≤3=4, ≤10=3,
  ≤30=1, miss=−2) vs 이진 ablation.
- **H8. 형식 게이트는 1.2B에서 필수다.** [근거] Search-R1 7B는 불요했지만 ≤3B는 전원 필요.
  DeepRetrieval: 위반 −4 + 과제보상 0. [검증] 게이트 유/무 초기 100스텝 비교.
- **H9. 형식 보상은 곱셈(게이트)이 덧셈보다 안전하다.** [근거] SoG-R1: 형식×정답×효율 —
  오답에 효율 보상이 새지 않음. R1-Searcher의 보상 해킹 사례(가짜 문서 생성 등).
  [검증] 보상 해킹 패턴 로그 감시.
- **H10. 소형 모델일수록 밀한(step별) 보상이 유리하다.** [근거] StepSearch: 3B +11.2pt vs
  7B +4.2pt — 작을수록 이득 큼. [검증] 2단계(다중턴) 진입 시 step 보상 포함.
- **H11. 검색 억제 보상은 아직 이르다.** [근거] IKEA는 "검색 안 해도 아는" 모델용 — H2에 의해
  우리 모델은 검색 없이 못 함. [검증] 보류(파라메트릭 정답률 실측 후 재고).

## C. 알고리즘·규모 (H12–H16)

- **H12. 1.2B 다중턴 순수 RL은 실패 확률이 높다.** [근거] 발표된 최소 성공 3B(그마저
  Musique 0.049로 바닥). SoG-R1: SFT 워밍업이 +40pt, RL 단독은 유의미하게 열세.
  [검증] 단일턴부터. 다중턴은 SFT 워밍업(교사 궤적 증류) 후에만.
- **H13. 단일턴 쿼리 재작성은 1.2B에서 될 가능성이 가장 높다.** [근거] DeepRetrieval 3B
  PPO로 GPT-4o 3~10배. 신용 할당 최단·마스킹 불요. [검증] 1단계 본실험.
- **H14. 붕괴는 예외가 아니라 기본값이다.** [근거] ReZero 450~700스텝 0% 붕괴, Search-R1
  GRPO 후반 붕괴, SearchGym 로그 ~160스텝 붕괴. [검증] 25스텝마다 held-out 평가,
  최고 체크포인트 채택, 500스텝 상한.
- **H15. KL=0은 위험하다.** [근거] R1-Searcher: KL=0에서 헛소리 출력. TRL 기본은 0.
  [검증] β=0.001 고정(문헌 표준).
- **H16. 작은 그룹이 오히려 안정적일 수 있다.** [근거] Search-R1: GRPO 그룹 1이 그룹 5보다
  안정·일반화 우수(반직관). [검증] 그룹 8 기본, 불안정 시 4→1 축소 ablation.

## D. 전이·평가 (H17–H20)

- **H17. 학습 reward 상승 ≠ 검색 개선.** [근거] SearchGym 실패의 교훈 + 오늘 modal_grounded
  검증 경험. [검증] 판정 기준은 held-out hit@k만. 학습 reward는 참고치.
- **H18. 개선분은 재작성 능력이지 코퍼스 암기가 아니어야 한다.** [근거] 시뮬레이션 과적합.
  [검증] held-out은 문서 단위 분리(같은 회의의 다른 질문도 금지).
- **H19. RL 모델은 무학습 1.2B와 프롬프트 재작성 baseline을 이겨야 한다.** [근거] RL-QR:
  무학습 LLM 재작성은 검색을 −27%까지 해침 — 지는 baseline이 아님. [검증] 3조건 비교:
  질문 그대로 / 무학습 재작성 / RL 재작성.
- **H20. 여기서 배운 재작성은 챗봇 검색으로 전이된다.** [근거] S3→GAIA 전이(+31%), 단
  보장은 없음(S3 저자 명시). [검증] 최종: KnowledgeChatService 검색 경로에 재작성 삽입
  A/B — known-item + 사람 판단.
