- RESOLVED: Independent concurrency/security audit (2026-07-04) found and fixed 4 real defects with no API keys required: (1) `ChunkingService.rechunk` had no document lock, so concurrent rechunks for one doc could interleave delete/embed/save and leave stale search chunks — now serialized via `DocumentService.getLocked` (PESSIMISTIC_WRITE). (2) `Document` had no `@Version`, so the Monday-Friday 9am `StalenessJob` (no lock) could silently overwrite a document a user had just verified — added `@Version` (V5 migration) and reworked the job to run per-document under a pessimistic lock with a staleness re-check, skipping on optimistic-lock conflict instead of failing the whole batch; conflicts now map to 409 for API callers. (3) `HeaderAuthFilter`'s internal-token comparison used `String.equals` (timing side-channel) — switched to `MessageDigest.isEqual`. (4) editing-plane `flushSnapshot`'s null-editor guard checked the timer map, which a retry had already cleared on its first attempt, silently dropping the snapshot — retries now force the pending flag. A candidate fix for Slack duplicate-ingest (claim the thread via the ingest log before the expensive summarize call) was tried and reverted: it requires a placeholder document to satisfy the `slack_ingest_log.document_id` FK, and catching `DataIntegrityViolationException` to distinguish "lost the race" from "genuine DB error" is unsafe once Postgres marks the transaction aborted after a constraint violation. The underlying race (wasted LLM call + duplicate Slack reply on truly concurrent reactions on the same thread) remains and is low severity — the unique constraint already prevents a duplicate persisted document. Full `./gradlew clean build` (Testcontainers, M0-M6) and a live `docker compose up -d && bootRun` curl smoke test (space/document/blocks/verify/internal-token paths) both passed after these changes. Three IDOR-shaped findings from the same audit (any member can rename/edit any document; MCP `create_draft`/`get_document` cross spaces) were checked against `03-api-spec.md`'s permission table and rejected as by-design: only verify/archive/owner-change are restricted to owner/ADMIN, and there is no space-membership concept in the spec at all.
